For a new animation the user usually shares a storyboard (photos, sketches or a page) and the line it illustrates.

1. Read the storyboard and the surrounding script (see "Working from a script" below).
2. Ask the questions that change the build first: what the borders or data come from, the look, the framing, where the
   images come from, anything ambiguous in the storyboard.
3. Show quick still previews of the candidate looks side by side, as numbered stills (never overwritten).
4. Only when the user has picked and tuned a look, build the animation.

## Working from a script

When the user sends lines from a longer script one at a time:

- **Build only the lines the user sends.** The full script is context, not a to-do list; never start on lines that
  haven't been sent.
- **Read the lines around each one** in the newest version of the full script before designing: what comes before and
  after changes what the shot has to show and how it hands over to the next.
- **Flag mismatches** between the line sent and the full script (wording, a date, a name) instead of picking one silently.

**Why:** a question or a still costs minutes; a wrong build costs a review round. A line read on its own can be built
for the wrong moment in the story.

**How to apply:** verify facts as you go ([[verify-facts-on-screen]]), number every render ([[keep-every-render]]) and
deliver at 4K ([[delivery-4k]]).
