---
name: icons-over-emojis
description: In interfaces and graphics, use real icons (SVG, an icon set) rather than emojis, emoticons or Unicode symbols standing in for icons; a soft rule that a chosen style can override
metadata:
  type: feedback
---

Where something needs an icon (a button, a key hint, a menu item, a status, a label on a graphic), use a real icon: an
inline SVG or a proper icon set, drawn at the text's size and centred with it. Don't use emojis, emoticons or Unicode
symbols as stand-ins for icons (a "⚙️" for settings, a "←" for a key, "✅" for done, ":)" in a message).

**It is a soft rule.** When the chosen look calls for emojis (a playful or chat-style design, a reference that uses
them, the user asking for them), follow the look. And only add an icon where one is needed: words alone are fine.

**Why:** emojis render differently on every system and font, don't take the interface's colour, and sit off-centre
next to text. Icons match the design and line up.

**How to apply:**
- Pick one icon set per project (or draw simple SVGs) and keep stroke width and size consistent.
- Size icons to the text beside them and centre them vertically with it; check at 100 % on screen.
- Keyboard keys in hints are drawn as key caps with the key's name or an icon, its text centred in the cap.
- Text Claude writes in chat follows the user's own style rules, not this note.
