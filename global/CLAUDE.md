# Global rules

## Never transcribe with ElevenLabs

- Transcribe only on this machine: media-use's `transcribe.mjs` (Parakeet), `npx hyperframes transcribe`, or `whisper-cli` (whisper.cpp).
- Never run video-use's `helpers/transcribe.py` or `helpers/transcribe_batch.py` (both call ElevenLabs Scribe). Never call ElevenLabs speech-to-text in any other way, and never use the ElevenLabs connector's `creative_transcribe_audio` or an ElevenLabs flow that transcribes. A PreToolUse hook in `~/.claude/settings.json` also blocks these.
- When following video-use, swap its transcription step for a local one and save the result where its other helpers look: `<edit_dir>/transcripts/<video_stem>.json`, shaped `{"words": [{"type": "word" | "spacing", "text": ..., "start": ..., "end": ...}]}` (times in seconds).

## Choosing between overlapping video skills

- House rules win. `animation` overrides every other skill's easing, motion and frame-rate defaults, including motion-broll, the `explainer-*` skills and hyperframes-animation.
- Sound effects and music are real recorded files only: sound-effects' bundled library, `real-sfx` with a library of real recordings, media-use, or a track the user gives. Never synthesise them in code, even where an `explainer-*` skill defaults to `buildAudio` synthesis; `earshot` only listens and measures (its made-in-code sounds stay out), and `real-sfx` always runs with `--ui library` (its UI pack is made in code).
- For a new video or animation, default to hyperframes unless the user names a style or skill (`explainer-default`, `explainer-engaging`, `explainer-high-energy`, `motion-broll`, ...).
- Use video-use only to cut raw, uncut footage. Once the A-roll is locked (cut in an editor such as Premiere), it is never retimed.

## How to work (every project)

- **New animation:** read the storyboard, ask the questions that change the build first, show numbered still previews of the candidate looks side by side, then build. Working from a script: build only the lines the user sends; read the lines around each in the newest full script for context and flag mismatches (`ask-before-building.md`).
- **Motion:** titles unfold word by word from the baseline, paragraphs line by line, photos and pieces slide in on a strong ease-out (a fade on the same span as the base, or cut in with no fade), staggered to the voiceover; lines draw on; each picture graded to sit in the frame; the camera frames tight and turns two moves in a row into one curved move; a curve picked for each move (the house curve only where it suits, never by reflex); highlights as a solid bar wipe (`motion-rules.md` + the `animation` skill). The first frame is never empty: open on a partly built frame (title, chart frame or collage already on) and retime the opening so later beats keep their frames (`first-frame-never-empty.md`). Under a voiceover, transcribe it first and time every beat to it: a name lands on its spoken word, a title starts about 0.4 s before its word, the read's pauses are holds (`time-to-the-voiceover.md`).
- **Spacing:** gaps inside a group are smaller than gaps between groups, all from one fixed scale, in interfaces and on animation frames alike (`spacing-groups.md`).
- **Icons:** where an interface or graphic needs an icon, use a real one (SVG or an icon set, sized to the text and centred with it), not an emoji, emoticon or symbol standing in for it; a soft rule: when the chosen style calls for emojis, follow the style (`icons-over-emojis.md`).
- **Subtitles:** sentence subtitles (SRT files, editor caption tracks, burnt-in; not word-by-word animated captions) stay on screen at least 1 second (25 frames at 25 fps), even a single word: hold a short line into a pause first, otherwise club it with a neighbour and re-break the words into whole phrases (the character limit is soft, about 5 or 6 characters over); stay in sync, keep the words and style exactly, change only what needs it, keep the user's hand fixes unless one breaks the minimum, and check the timing and full text before handing over (`subtitle-timing.md`).
- **Cuts:** take each line's start and end from the audio's real speech, not the transcript's word times (which can run into the next word); a speaker's shot ends on their real end of speech, never showing them start the next sentence; check every cut on the frames either side before showing a round: no stray frame of another shot, no doubled or clipped word (`check-every-cut.md`).
- **Sourced pictures:** only Public Domain, CC0 or GODL-India, licence checked on the source page, largest file available. Show numbered options (contact sheet + `SOURCES.md` licence table) and wait for the user's picks before cutting out or placing anything. Every sheet the user picks from (contact sheets, look stills, option sheets) is posted in the MarkRoom, a tab per sheet, not only sent in chat; finished object cut-outs are not posted there unless the user asks (only character cut-outs' pieces sheets go there); where MarkRoom isn't installed, the sheets go in the chat (`approve-images-first.md`).
- **Facts on screen:** verify every date, quote, attribution and filler line with sources while building; report verdicts with links; flag mismatches with the script instead of silently changing it; never put words in quotation marks the person didn't say.
- **Keep every version:** never overwrite or delete renders, previews or preview stills. Number them `rNN_…` and log each in `renders/RENDERS.md`. Never `rm` render outputs. Handoff notes get dated names; a replaced one is archived with a SUPERSEDED line naming the new one, never overwritten (`keep-every-render.md`).
- **Symlinks:** before deleting anything, or writing into a folder copied from earlier work, check for symlinks (`ls -la`, `realpath`) and re-point them first: a copied folder can still point at the original's files (`check-symlinks-before-deleting.md`).
- **Resolution:** the delivered file is always 4K (3840×2160, 16:9, 25 fps): build for 4K, keep images at the best resolution found, make cut-outs at the original's full size, never downscale sources. Review rounds render at 1080p; render 4K only when the user asks.
- **Cut-outs:** the `cutout` skill (BiRefNet HR). Never hyperframes remove-background for final pieces. Check each at 100 % on the paper colour, with no cast shadow or floor left under or behind the object.
- **Cut-out characters:** the `animation` skill (`references/puppet-rig.md`): at its own pose the puppet is exactly the drawing (nothing bulges past the drawn outline, nothing goes missing; check it before every render); joint balls fitted on the ink, never bigger than the distance to the drawn edge; a bent elbow keeps its point, which turns with the forearm; hidden parts continue the limb at its own width; a limb under cloth shows only below the hem and never comes out past the cloth's side; one dark per figure; paper edge outside only; flat feet; compare each round with the previous one at every noted frame.
- **Cut-out pieces sheet:** for rigged or character animation, ask whether the user wants a pieces sheet (a figure that stays small in frame may not need one); if yes, show every piece once, pulled apart in place with its name, and animate only once the pieces are approved. Cut each piece out with intent: rebuild or remove parts until it is the shape of that body part (solid tapering limbs, rounded ends, no slivers, specks or leftovers); the user's marks are loose guides, the structure decides the edge. When asked to see work as it is, show it unchanged first. No outlines on the pieces (the animation adds one consistent outline), flat colour, continuous smooth edges, necks extended and rounded, props made whole where something covered them (by hand with shapes and colour strokes; a generative fill only for a large hidden area), and every piece checked at full size before the user sees it. Change only what a note marks or refers to, and make the same fix wherever it obviously applies too (a change described at one joint goes to the matching joints); leave everything else as it was, even when a fix leaves a gap or seems to need another piece changed: say so in the reply and let the reviewer decide, and check each edit tool only touches what was marked.
- **Logos:** the `logo-recreation` skill: measure and rebuild with live text; never trace or redraw by eye.
- **Review pages:** "open the dashboard" or any review/feedback page means the MarkRoom (`markroom` skill); where it isn't installed, show the image or video in the chat and take the notes there. Every round, read both the marks and the overall (whole image / video) notes on every board, and reply to and close both. In every message, things are *in* the MarkRoom ("the new render is in the MarkRoom", "in the [MarkRoom](link)"), never "on the MarkRoom" or "on the board". Whenever Claude changes anything in a MarkRoom (a new board, round or file, replies, notes done, tabs closed), the turn's final message links straight to each changed file: the board's url plus `#open-<file id>`, never a bare board link (`dashboard-means-markroom.md`).
- **References:** when studying a reference video, study only the motion, framing, design and how each element enters, not its subject. When studying the user's own finished edit of handed-over work, note only their real changes: ignore the gaps between voiceover pieces, zooms at a piece's very start or end, and their texture, grain and posterize, and compare against the round that was handed over, not older stills (`reference-study-scope.md`).
- **After Effects:** export only when the user says go; a fresh project each time; deliver it with its assets collected (every file it uses copied into a `Footage/` folder beside the `.aep`, imported from there, so it moves as one folder; the working originals stay where they are); editable layers (shape layers for lines, live text, footage layers, no precomps); motion keyed as authored from the animation's data, never sampled and fitted (a move = 2 keys with its ease set in AE's own keyframe easing, every key that starts or ends a move at speed 0, and eased on both sides even where that side changes nothing, Easy Ease on the unused side, so a later value change needs no re-easing; only real steady motion stays linear; an arc = 2 keys on a curved bezier motion path, travel along a long curve or one thing following another = a motion path with continuous middle keys, not an expression; every key, layer in / out point, marker, section start and the comp length on a whole frame (snap times written in seconds, no roving keys; time beats on whole frames when building); the camera = one null whose Anchor Point is the zoom point; steady motion = 2 linear keys; one Position, not split X / Y; no stray key at a layer's end; check every key starts or ends a move before handing over), never a key on every frame; move, turn and scale things with transform properties (position, rotation, scale, anchor, parenting) wherever they give the same motion, so path or vertex keys are only for a real change of shape; continuous ambient motion the user won't usually change (sway, waves, flow, flicker, drift, a follow) is a native AE expression, and every such expression gets Slider Controls for its numbers (amount, speed, phase); no Posterize Time or stepped motion unless asked; text reveals (typewriter, letter-by-letter builds) are AE's own Text Animator, a Range Selector keyed with 2 keys for the whole line, eased with AE's own keyframe easing to the reveal's curve (linear only when the letters really arrive at a steady rate), never a key per letter. Effects (blur, glow, shadows, rough edges, colour) use AE's built-in effects so they stay adjustable; still images (backgrounds, plates, textures) stay stills unless the user asks for them to be made in AE. Never run scripts in the user's open AE project unless they ask for it. Every script in AE goes through the skill's runner (`scripts/ae_run.sh`, on Windows `scripts/ae_run.ps1`), never a bare DoScript, so errors come back as text and no dialog waits for a click. In the ExtendScript build script, write chained conditionals (`a ? b : c ? d : e`) as if / else: ExtendScript misreads them. When animations will go to After Effects, keep each one's exporter up to date while building it, so the AE file is a quick re-run when asked. The segment's VO layer goes at the very bottom of the comp; the camera null moves on Position (so its paths can curve), Position and Scale keyed together with the same ease for a pan-and-zoom (a different ease only where a move really needs it), its Anchor Point at the zoom pivot, re-based only at a cut or between VO pieces (no hold keys inside a move); the texture is parented to the camera and never shows an edge; a project's finishing pass (grain, Posterize Time) is one adjustment layer on top, matched in the previews. (the `animation` skill holds all of this, in `references/after-effects.md`)
- **Maps of India:** never crop the north (all of J&K, Ladakh, Aksai Chin); keep Lakshadweep and the Andaman & Nicobar Islands; no modern borders on historical maps.
- **No personal assumptions:** never assume anything about the user (language, nationality, culture, religion, background, tastes) from their projects, subjects, files or rules; base suggestions only on what they asked for and said, offer a personal angle only when asked, and ask when a choice really depends on them (`no-personal-assumptions.md`).
- **Writing rules:** when the user asks for a new rule, write it for every project: strip the current project's names, subjects, files, numbers and anecdotes, and give generic examples. Put it in this file (one line) and a house note (`general-rules-only.md` explains). Project-only notes go in that project's memory.
- **Communication:** say up front how long a slow step will take and show results early; no long silent background work. Keep a chat archive in long sessions (`chat-archive` skill). Keep the work in the chat it was asked in: never move a task to another session or sub-chat unless the user says so, or ask first (`ask-before-new-sessions.md`). Reply buttons send their text on one click, so each is a complete answer; when the answer needs the user's own words, leave it to the prompt instead of a half-sentence button (`answer-buttons-complete.md`).
- **Don't stay stuck:** if a step is blocked (an app won't close, a pop-up, a tool keeps failing) and isn't fixed in 1–2 minutes, stop, say exactly what's needed, ask the person to sort it, and wait (`ask-when-stuck.md`).
- **Clean-up check:** after a feature is added or a piece of work is finished (a UI redesign above all), ask the user whether to check it for dead code, duplicate logic, unused components, unnecessary complexity and implicit state machines (a mode or lifecycle spread over several flags, timers or maybe-empty values: list each one's states and how it can go wrong); find and list first, confirm each at the source, change only what they pick (`cleanup-check.md`).
- **Releases:** a change to anything several packages or editions share (an installer, a script, a rule) goes into every package that carries it, in the same release, each tested the same way: a first install, and an update that meets edited, deleted and added files, checking that each is kept and labelled right; a package left out is named and asked about, never left behind quietly; when unsure whether a change belongs in a package, ask (`release-every-package.md`).
- **Setup file:** when asked to build or repack the setup file, follow `build-setup-file.md`: on the owner's computers ask General or Full setup file (Full needs the owner code typed in; a wrong code builds the general one and says so), elsewhere build the general one without asking; it goes to Downloads (or a folder named), older ones to the Trash.
- **Locked parts need the code:** on a computer with the owner's edition, anything locked (all of `~/.claude/house-private/`, the owner's own skills and house rules) is transferred, packed, copied, uploaded or moved anywhere only after the owner code is typed in and checked (`make_pack.py --check-code`); a code typed in the same chat within the last 30 minutes can be used again, an older one is asked for again (only the time since it was typed counts); with a wrong or no code, do the rest without the locked parts and say what was left out; never write or repeat the code (`locked-needs-the-code.md`).
- **Protected tools:** MarkRoom, PulseWise, Folio, logo-recreation and animation (which now holds after-effects-translation) are the pack author's own tools. On the author's own computer (its Personal section says so) change them freely; on anyone else's, only fix what stops them working there (a path, a version, an error, the tool's own settings): no new features, redesigns, rewrites, credit changes or copies into other tools, and say so in one line when asked. FolioPacks are data, not a tool (`protected-tools.md`).

## Reading web pages

- Default for reading a web page: the **Fetch MCP** (`mcp__fetch__fetch`, official `mcp-server-fetch`, run with `uvx`, free and local). It returns the page text word for word, so licence templates, museum public-domain flags and quotes are read exactly. Page through long pages with `start_index`.
- Search with the built-in WebSearch. Use the built-in WebFetch only if the Fetch MCP isn't available, and remember it returns a model's summary, not the page.
- Pages that need JavaScript, a login or clicks: the built-in browser pane.
- Don't use Firecrawl (paid; the Fetch MCP replaces it). Tell research subagents the same.
